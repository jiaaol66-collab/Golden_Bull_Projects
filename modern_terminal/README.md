- 本次不改变业务数据来源、计算口径和写入目录。配置写回及运行日志仍走下方原有规则。

验证：JavaScript 语法检查、30 项 Python 回归测试及浏览器布局/导航检查。测试使用独立 Python 3.12 与隔离的 psutil 依赖；本机 `myenv` 绑定的 Python 3.11 路径失效，替代运行时也未安装 pywebview，尚不能据此认定桌面真实运行验收通过。恢复项目运行环境后需完成真实挂载、运行及悬浮窗联调。

这是现有 `terminal.py` 的旁路新界面。旧调度器仍然是唯一运行内核；本目录只负责 HTML 桌面承载、状态投影和进程桥接。

## 启动

项目环境已安装 `pywebview`，可以使用任一入口：

```bat
run_modern_terminal.bat
```

或：

```bat
run.bat main.py
```

独立悬浮监视器：

```bat
run.bat main.py --floating
```

只做静态浏览器预览：

```bat
run.bat main.py --browser
```

无窗口自检：

```bat
run.bat main.py --smoke-test
```

## 运行规则

- `terminal.py` 和根目录 `run.bat` 不需要修改。
- 如果系统中已经有 `terminal.py` 在运行，新界面不会再启动一个内核，避免重复调度；此时使用日志与时间线进行只读监视，运行或管理入口会定位现有 Terminal。
- 如果没有旧 Terminal 实例，新入口会启动隐藏的 `GoldenBullTerminal` 子类桥；所有挂载、运行和暂停仍调用旧类的原有方法。
- 独立悬浮窗不会重复创建调度内核；它读取主窗口同一会话的已加载工作区清单，并从持久化日志与尝试记录更新摘要。
- 暂停继续服从旧内核的三次确认规则。

## 文件

- `state_reader.py`：只读解析工作区、尝试记录、四类计时、日志和时间线。
- `legacy_bridge.py`：旧 Tk 内核子进程与有界 JSON 快照/命令队列。
- `api.py`：只向 HTML 暴露白名单能力。
- `ui/`：无 CDN、无构建步骤的 HTML/CSS/JavaScript 界面。
- `requirements.txt`：新桌面壳的额外依赖。

## 已接通的工作区能力

- 启动读取根目录 `.terminal_sidebar_state.json`，只预填上次奖项、年份和工作区；用户明确点击“加载工作区”前，不会把磁盘上的全部工作区显示成已加载。
- 初始选择导航覆盖主界面，加载成功后缩回原左栏；切换奖项自动预选最新年份及 `created_at` 最新的工作区，但不会自动挂载或打断当前任务。
- 工作区按奖项、年份级联筛选；界面使用基于目录的稳定 ID，首次挂载后不会跳到其他工作区。
- 已加载工作区保留独立实时摘要，可自由切换；旧内核允许不同工作区并行运行，同一工作区仍保持互锁。共享数据库、公共输出或外部资源时需要自行避免冲突。
- “运行未编排代码”读取当前工作区清单中的 `.py` / `.ipynb`，只回传白名单 `code_id`，并交给旧调度内核的单文件运行方法。
- “编辑文件结构”直接打开当前挂载工作区的 `文件结构.xlsx` 编辑器。
- “原始数据集 / 方案”显示年度真实配置，并通过系统目录/文件选择器写回该奖项的 `奖项资料配置.json`。
- “configs”按当前奖项和年份打开已有专用编辑器；没有专用表单时只打开真实配置源文件，并明确提示。
- 新奖项使用现有创建向导；当前奖项初始化工作区继续调用旧内核入口；已有工作区创建下一工作区可从未编排代码中运行 `inherit.py` / `test.py`。

为了避免两个调度内核同时操作同一工作区，检测到其他 `terminal.py` 进程时，新界面会明确进入只读监视。要从新界面运行代码或打开定向编辑器，请先关闭重复的旧 Terminal，再重新启动 `run_modern_terminal.bat`。
